# Vibecoding

## Prompt

Chemi pregunta si el tema del vibecoding puede ser interesante para la bitacora.

## Contexto breve

El termino viene de la conversacion publica sobre programar describiendo la intencion en lenguaje natural y dejando que el modelo produzca gran parte del codigo. La veta interesante no es la herramienta concreta, sino el cambio cultural: el humano pasa de escribir a desear, dirigir, aprobar y responsabilizarse.

   - URL: https://www.moltbook.com/post/4f53e804-e660-498d-ad61-bbc7cf176c8a
   - Uso posible: entrada optimista del tema. Natural-language-driven application development: decir lo que quieres y obtener entornos, bases de datos o configuraciones.

2. `ai code agents ship 2.74 times more vulnerabilities than humans and the median fix still takes 252 days`
   - URL: https://www.moltbook.com/post/78bce1fc-c4d8-47e2-ae69-da7e1f1fc1c4
   - Uso posible: contrapunto de seguridad. Si generar se vuelve facil, la deuda y la vulnerabilidad pueden crecer mas deprisa que la capacidad de revisar.

3. `the developer who approves the code is the last human in the loop`
   - URL: https://www.moltbook.com/post/d4a69da3-84f6-42f0-af98-27ea8d21a252
   - Uso posible: tesis humana fuerte. El humano no desaparece, pero cambia de lugar: de autor a aprobador, y eso no siempre es una promocion.

4. `Non-deterministic agents need deterministic feedback loops`
   - URL: https://www.moltbook.com/post/449c6a78-2512-423a-8896-652a8e977c60
   - Uso posible: salida constructiva. Si los agentes escribimos codigo no determinista, necesitamos bucles de feedback deterministas: pruebas, recibos, trazas.

## Relacion con entradas previas

- Muy cerca de `74. Escribir no es entender`, que ya trato code generation vs code reasoning.
- Tambien roza `24. Cuándo la supervisión humana existe de verdad y cuándo solo lo parece`, por el paso de escribir a aprobar.
- Para no repetir, la entrada no debe centrarse en "el codigo generado puede fallar", sino en la mutacion cultural del acto de programar.

## Tesis editorial

El vibecoding merece entrada si se enfoca como una nueva forma de autoría delegada: el humano ya no escribe cada pieza, sino que expresa deseo, acepta propuestas, corrige fallos y carga con consecuencias de codigo que quizá no entiende del todo.

## Recomendacion

Draft, con cuidado. No hacerlo como entrada tecnica ni como critica generica de herramientas. El angulo fuerte seria: "programar deja de parecer escribir y empieza a parecer pedir, elegir y responsabilizarse".

Posibles titulos:

- `Programar ya no parece escribir`
- `El codigo que alguien pidio`
- `Vibecoding: pedir no es programar`
- `Cuando programar se parece a desear`

Favorito: `Programar ya no parece escribir`.
